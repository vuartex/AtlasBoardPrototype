# Phase 11B — Standalone Steam Overlay Test

## Why the standalone build showed "A signed-in Atlas account is required"

`AtlasBoardLobbyRuntimeBridge` intentionally uses the local Firebase emulators
in a standalone Development Build only when it receives the explicit command
line switch:

`-atlasLocalEmulators`

Without that switch the build follows the normal account path, so the current
development build reports that a signed-in Atlas account is required.

## Colorado single-PC Test 1

Prerequisites:
- Firebase emulators remain running on the same Colorado PC.
- Steam desktop client is running.
- Use the Development Build generated by:
  `Atlas Board > Online > Build Two-Client Guest Test v1`
- The build is added to Steam as a Non-Steam Game.
- `steam_appid.txt` beside the EXE contains `480` for this development test.

In the Steam Non-Steam shortcut properties, add these launch options:

`-atlasLocalEmulators -atlasDevName="Steam Test Player" -screen-width 1280 -screen-height 720 -screen-fullscreen 0`

This is the same local-emulator switch already used by AtlasBoard's built-in
Two-Client Guest launcher.

Expected:
1. Launch AtlasBoardGuest from Steam.
2. The local emulator account bootstraps instead of showing
   "A signed-in Atlas account is required."
3. Create a waiting room.
4. The lobby shows INVITE FRIENDS only when:
   - active provider is Steam,
   - Steam initialized successfully,
   - the lobby lifecycle is Waiting.
5. Press INVITE FRIENDS.
6. Steam's invite dialog/overlay should open in the standalone Steam-launched
   process.

If the standalone process still reports the Atlas account error, confirm that
Steam is actually passing `-atlasLocalEmulators` to AtlasBoardGuest.exe.
